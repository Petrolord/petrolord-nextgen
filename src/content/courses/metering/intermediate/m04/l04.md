# One vocabulary, two functions

Two different functions in this module talk about inherent characteristics. One recommends a characteristic from the authority. The other checks valve travel and needs to be told which characteristic is fitted. A course full of words on a screen only works if those two functions mean the same thing by the same word.

## The assertion

They do, and it is asserted on every row of the authority ladder rather than assumed: every id the recommendation returns is an id the travel check accepts. The ids in play are `equalPercentage` and `linear`, with the labels equal percentage and linear beside them.

That sounds like housekeeping. It is the difference between a tool a designer can work through end to end and a tool that hands back an answer the next step cannot use. A recommendation phrased in a vocabulary the travel check does not recognise would strand the user at exactly the point where they were doing the right thing.

## What happens outside the vocabulary

The travel check refuses anything it does not know rather than guessing:

> `unknown inherent characteristic 'quickOpening': this module knows equalPercentage and linear. An unrecognised characteristic used to be treated silently as equal percentage`

Quick opening trim is a real characteristic and a common one on valves that are there to dump flow rather than to modulate it. The point of the refusal is not that the characteristic is illegitimate. It is that this module does not carry the curve for it, and a travel percentage computed on the wrong curve is a number that looks perfectly plausible and is wrong by a large margin at both ends of the range.

## The general lesson about shared vocabularies

Anywhere two functions exchange a word rather than a number, three things need to be true. The set of words one produces has to be inside the set the other accepts, which is the assertion above. Anything outside that set has to be refused by name rather than mapped onto a default. And the refusal has to say which words are known, which this one does, so the user can act on it without reading the source.

A silent default is the failure mode to watch for, because it produces an answer of the right type and the wrong value, and nothing downstream can tell that it happened.

It is worth noticing where the refusal is placed. It fires at the travel check, which is the function that was handed the unknown word, rather than at the recommendation, which never produces one. A refusal belongs at the boundary a bad value crosses, because that is the only place that knows both what arrived and what was expected of it.
