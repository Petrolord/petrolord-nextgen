# The common element

One element can serve both envelopes. When it does, the two barriers you drew are not two, and the engine says so.

{{panel:wi-envelope-explorer}}

## What both means to the engine

The envelope field accepts a third value alongside primary and secondary. An element marked both is pushed into the primary list and into the secondary list, and its name is collected into a separate list of shared elements.

The engine then runs a named check over that list: no element shared between envelopes. If the list is empty the check passes. If it is not, the check reports and names every shared element, with the note that it requires explicit acceptance.

The published teaching well has an empty shared list, so that check passes cleanly. Most real wells do not stay that way for long.

## Why it wrecks the premise

Go back to the argument for two barriers. The first one failing has to be an event you survive, and you survive it because the second one is untouched by whatever killed the first.

A common element is a place where that sentence is false. Whatever defeats it defeats both envelopes in the same instant. There is no interval to detect anything, no intact backup to hold while you intervene, and the well behaves exactly like a well with one barrier at the moment it matters.

Watch what the rollup does with it. Suppose the wellhead were marked both, and suppose it failed. The failure enters the primary list and the secondary list, so both envelopes roll up to failed. Two failed envelopes on a well with flow potential is red, and the reason the engine gives names one barrier failing while the other is degraded, failed or missing.

Compare that with the published well, where the degraded safety valve sits in the primary envelope only. Re-rate that valve to failed and the primary fails while the secondary stays intact, which is orange. Same single element, same single failure, two categories apart, and the only difference is whether the element was doing one job or two.

## Flagged, not forbidden

The check is a warning rather than a hard failure, and that is a considered choice rather than a soft one.

Some wells genuinely cannot avoid a common element. A wellhead is the honest example: it is hard to route a primary and a secondary envelope to surface without both passing through it. The convention this engine follows treats such an element as acceptable only by deliberate dispensation, which means somebody senior wrote down that they knew, why it was unavoidable, and what compensates for it.

What the engine refuses to allow is that the sharing goes unnoticed. It names the element every time, in every run, so nobody can read a barrier table and count two envelopes that are secretly one.
