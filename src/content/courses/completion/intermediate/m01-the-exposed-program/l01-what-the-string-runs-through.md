# What the string runs through

The casing program stops being a lookup and becomes the object every check in this tier reads.

{{panel:cd-clearance-explorer}}

## Two strings, three segments

The published well has two casing strings. A nine and five eighths inch production casing from surface to three thousand metres, run in two sections of different weight with the change at sixteen hundred and fifty metres. And a seven inch liner from twenty four hundred metres to three thousand.

Those two strings overlap over the bottom six hundred metres, where both are present and the liner is inside the casing.

The exposed profile is what the completion actually sees, and it has three segments: the two casing weights down to twenty four hundred, and the liner below it.

## The nine and five eighths casing is still there

Below twenty four hundred metres the production casing has not gone anywhere. It is still in the hole, still cemented, still doing its job. It simply is not the bore the completion passes through, because the liner is inside it.

That is worth being explicit about, because a profile that shows the liner below twenty four hundred looks like the casing stopped there, and it did not. The profile is a record of what is innermost, not a record of what exists.

## What a profile row carries

Each row is a depth interval with an inside diameter, an outside diameter, a drift and a label naming the string it came from.

The label is not decoration. When a clearance check fails, the first question is which string caused it, and the label is the answer. A number without a label sends the reader back to the program to work out which string was at that depth, which is the calculation that just ran.

## Why this has to be built rather than looked up

Because the answer at a depth depends on every string that reaches it. A lookup of the form what casing is at two thousand five hundred metres has two correct answers in this well and only one of them is the one the completion cares about.

Building the profile resolves that once, in one place, and every check downstream reads the resolved answer.
