# Embedded is earned

"Embedded" is the lesson status that says the organisation has not only accepted a lesson but built it into how it works. The engine allows a lesson to be marked "Embedded" only when its application log shows it changed something.

{{panel:rc-review-explorer}}

## Where Embedded sits

The legal move into "Embedded" is from "Published". From "Embedded" the only moves are to "Superseded" and to "Archived". Embedded is a visible status and an accepted one, so an embedded lesson is still read and still reviewed.

What the move asks for is evidence that the lesson was applied somewhere and changed it.

## Three lessons asked to embed

The digest asks the engine to mark three published lessons "Embedded":

- ALLOWED, ON-01 marked Embedded.
- REFUSED, ON-03 marked Embedded, its one application a rejection: This lesson has been considered 1 time and adopted nowhere. Record where it was applied before calling it embedded.
- REFUSED, ON-04 marked Embedded, with no application at all: Record where this lesson was applied first: the risk it raised, the change it caused, the procedure or the course it altered. A lesson that changed nothing has not been learned.

ON-01's reuse record shows 2 applied, an adoption into the "Risk register" and an adaptation into a "Procedure". That is evidence of use, and the engine allows the move.

## Considered is not applied

ON-03 has an application, so it has not been ignored. Its one application is a rejection, and the refusal says exactly that: considered 1 time and adopted nowhere. The engine counts the consideration, which is honest, and still refuses the status, which is correct. Somebody weighed the lesson and decided against it. That is a real record and embeds nothing.

The refusal also names the way forward: record where it was applied. If the lesson has since been used and nobody logged the use, the fix is to log it.

## Nothing recorded at all

ON-04 has no applications. Its refusal lists the kinds of change an application records: the risk the lesson raised, the change it caused, the procedure or the course it altered. And it ends on the sentence this whole module rests on: a lesson that changed nothing has not been learned.

## Why the status has to be earned

If "Embedded" could be set by hand, it would drift toward meaning "important" or "old", and a dashboard counting embedded lessons would measure how often somebody clicked. By tying the status to the application log, the engine makes every embedded lesson checkable: open its reuse record and the targets it changed are listed there.

ON-02 on the ONNE register is already "Embedded", and its reuse record shows 1 applied, an adoption into "Management of change", naming the change ES-06. The last module of this tier follows that trail from the lesson into the change register.

Every answer here was also replayed through the independent oracle for lessonsLearned, so each is two methods agreeing.
