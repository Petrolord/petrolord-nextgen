# What the engines leave to people

An engine decides a state from a record by a fixed rule. Everything that goes into the record, and every choice about which records to hand over and on what date, stays with people. Each of those choices can change the answer on the screen while the rule stays the same.

## The record itself

None of the four engines stores anything. The app stores the record and asks the engine what it means. That makes the person who fills in the record the first author of every status. An assessor chooses the likelihood and the impact of a risk. The engine multiplies them. A bad choice is multiplied as faithfully as a good one.

The same is true of the residual levels. Deciding how far a control lowers the likelihood or the impact of a risk is a judgement about the facility. The engine reads the levels it is given and has no view on whether the control works.

## The target

Appetite compares the residual score with the risk's OWN target. The target is set by people for each risk. With no target, or a target of zero, the engine answers "Not set" and declines to report a pass. So a register where nobody has set targets cannot show a single risk within appetite, however low its residuals are.

## The date

Every function that takes a date defaults to the machine clock if the caller leaves the date out. The caller decides which date to hand in, and so decides which day the answer describes. This course hands in 2026-10-01 on every call, and every dated status it quotes is true on that date.

## The population

When a register is counted by band, the engine counts whatever list it is handed. It does not filter by status. The caller chooses which risks to hand over, every risk or only the live ones, and whether to count the inherent score or the residual score. Each choice gives a different, correct count for a different question, and the tile that shows the count has to say which question it answers.

## The status of the record

Whether a risk is "Open", "Mitigated" or "Closed" is set on the record by people. Here "Closed" is a status of a risk, the one this tier uses. The engine reads the status and applies the rule that goes with it: only a live risk carries a review obligation. Mark a risk "Closed" and its review stops being checked, whether or not the hazard has gone.

## The mistake

The mistake is to trust a status because an engine produced it. An engine guarantees that the same record, the same target, the same date and the same population always give the same answer. It guarantees nothing about whether the record describes the facility. That part of assurance is done by the people who keep the register.
