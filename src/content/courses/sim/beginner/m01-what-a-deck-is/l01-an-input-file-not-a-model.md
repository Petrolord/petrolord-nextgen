# An input file, not a model

A reservoir simulator is a program. Like every program it takes input, and its input is a text file called a deck. Everything the simulator will do about your reservoir is decided by text you can open in an editor and read line by line. This course is about reading and writing that text.

## What a deck actually is

Plain ASCII. Keywords in capitals, each introducing a block of data, each block closed by a slash. No binary, no database, no hidden state. A deck for the Ekene field is 940 lines long, and every one of those lines is a decision somebody made.

That is worth saying plainly because simulation has a reputation for being opaque. The opacity is real but it lives in the SOLVER, in what happens after the deck is read. The deck itself is the least mysterious part of the whole exercise. If you can read a deck you can audit a study, and if you cannot, you are taking someone's word for the answer.

## A deck is not a model

The distinction this lesson is named for matters more than it sounds.

A deck DESCRIBES a reservoir: this much rock, this shape, these fluids, these wells, this history. It is a description, and like any description it can be complete, incomplete, or wrong, and none of those states is visible from the deck alone.

A MODEL is what the simulator builds when it reads the deck and starts solving. That is where the pressure field lives, where the saturations move, where the mass balances close. The deck is upstream of all of it.

So a deck that a simulator accepts is not a deck that is right. Acceptance means the grammar parsed and the required blocks were present. It says nothing about whether the grid resembles the field, whether the fluid is the fluid, or whether the history you handed it is the history that happened. Those are separate questions and this course is about asking them.

## What is in the Ekene deck

Six sections, in a fixed order. A grid of 4500 cells. Tables describing how the oil, water and gas behave and how they compete for the pore space. A statement of where the fluids sat before anyone produced anything. Seven wells. Thirty six months of history, and a prediction tail after it.

Every number in it comes from somewhere the previous four courses of this module can name. The layer thicknesses are the waterflood course's layer column. The rock curves are the SCAL course's Corey design. The oil is the material balance course's tank fluid. The history is the waterflood course's monthly ledger. That is not a coincidence of teaching convenience; a deck is where all of it has to agree, and the places it fails to agree are the interesting part.

## Where a deck goes

To a simulator, which runs it and writes results. Petrolord's Reservoir Simulation Studio is where a Petrolord deck goes to be run.

This course does not cover running one. What you learn here is how to build a deck a simulator will accept and an engineer can defend, and how to read one somebody hands you. Those are separable skills from operating a solver, they are the ones that decide whether a study is trustworthy, and they are the ones that transfer between every simulator in the Eclipse family.

## The misconception to avoid

"The deck is generated by the software, so I do not need to read it." Something generated it, and that something encoded a series of choices: which convention, which contact, which fluid, which averaging. A generator does not remove those choices, it hides them. The deck is where they become visible again, which is exactly why it is worth reading even when you did not write it.
