# Two tables with the same numbers

Two engines in this package export the customary allowable radiant intensities: the pressure relief engine and the spacing engine. They carry identical wording, and a test asserts they stay equal. This lesson is about what that arrangement is worth, and it is the clearest small example in the course of a pin that looks like a check.

## The table, as both engines hold it

| kW/m2 | label in the relief engine | label in the spacing engine | equal |
| --- | --- | --- | --- |
| 1.580000 | Continuous exposure, no time limit (site boundary, control room) | Continuous exposure, no time limit (site boundary, control room) | yes |
| 4.730000 | Emergency action of several minutes, with clothing | Emergency action of several minutes, with clothing | yes |
| 6.310000 | Emergency action up to about a minute | Emergency action up to about a minute | yes |
| 9.460000 | Seconds only: escape route | Seconds only: escape route | yes |

Four rows, each a number and a label, exported as data from two engines that have no other reason to agree about anything.

## What is held here, and how completely

The values are customary and the wording is this package's own. No publication in this repository checks either. So the whole table is held for literature, which means it is taught as a stated limit and never as an answer, and nothing graded in this course reads a row of it.

Take the second half of that seriously. It is not just the numbers that are unchecked. The labels are an interpretation, written here, of what an intensity means for a person standing in it. A label carries more authority than a bare number, because it sounds like a finding, and this one is a form of words with no source attached in this package.

## What the equality test is for

The test does one thing well. It stops the two copies drifting apart, so a learner cannot meet two sets of words for one published table and an engineer cannot read one copy in one studio and the other copy in another.

It does not make either copy right. Both tables could carry the same wrong value and the same misleading label and the test would pass forever, because the test compares them to each other and to nothing else.

That is the whole distinction this module is building towards. A check compares a quantity against something derived independently of it. A pin fixes a quantity so it cannot move without somebody noticing. Both are worth having. Only one of them is evidence, and the audit module names every place in this engine where the second has been mistaken for the first.

## How to use a held table

Cite it as customary and name it as unsourced in this package. If a decision turns on which row you picked, go and find the publication, because the row is doing the work and the row is the part with no backing. If the decision does not turn on it, say what you used and move on.

The practical version of that rule appeared in the last lesson and it is the same rule. State your own allowable, source it, and write it beside the distance it produced. An allowable you stated can be argued with. A row of a table nobody can trace cannot, which makes it look stronger than it is.

## Exercise

Then write two sentences on what the equality test establishes and two on what it cannot, and give the general distinction between a check and a pin.
