# The fit reads data, not labels

A lab report arrives with a header: "Corey exponents $n_w = 2.5$, $n_o = 2.0$, per company standard." Below it sits a table of measured points. The header and the table do not have to agree, and when they disagree, which one is the rock? This closing lesson makes the module's deepest point with a planted experiment: the fit answers to the data alone, and that is precisely what makes it useful as an auditor.

## The planted disagreement

Take the same thirteen saturations as lesson 2's table, but generate the permeability columns from a DIFFERENT rock: $n_w = 1.2$, $n_o = 3.5$, same endpoints, same window. Suppose the table is then filed under the Ekene header claiming 2.5 and 2.0. Every individual row still looks unremarkable; nobody reads 0.19 at a saturation of 0.68 and smells a wrong exponent.

Hand the table to `fitCoreyToKrTable` and it returns $n_w = 1.2$ and $n_o = 3.5000000000000004$, with an rmsLog of 1.1610990315520314e-16, converging in 5 iterations from the same neutral start. The recovery is machine-perfect, and it is a recovery of what the COLUMNS say, not what the header says. The oil exponent's last-place digits are the familiar float story from lesson 2, and the iteration count barely moved even though the answer sits much further from the starting guess in one coordinate: the log-space objective is smooth enough that distance is cheap.

This is the same discipline the pore-pressure course teaches with its compaction trend, where the fitted normal-compaction line follows the twelve shale picks and not the header's advertised coefficients. A fit is an instrument you point at data. It has no access to the label, so its agreement or disagreement with the label is evidence, and it is evidence of exactly one thing: whether the table was generated by the curve the header claims.

## Using the fit as an audit tool

The practical workflow follows immediately. When a curve set arrives from any source, refit it before use:

1. Fit the table with endpoints pinned. Read the exponents and the rmsLog.
2. If the rmsLog is tiny and the exponents match the header, the set is internally consistent and honestly labelled. Use it.
3. If the rmsLog is tiny and the exponents CONTRADICT the header, the table is a clean Corey rock wearing the wrong badge. Trust the fit, flag the report, and find out what else in that report was transcribed from a different sample.
4. If the rmsLog is large, the table is not Corey-shaped at all. No exponent pair describes it, the header is not even wrong, and the honest path is the tabular kr specification the Associate tier taught, which carries the measured points directly into the fractional-flow machinery with no shape assumption.

Case 4 deserves respect rather than repair. The engine's displacement functions accept tables natively; forcing a Corey label onto a non-Corey rock trades a representation error you can see in the rmsLog for a hidden bias in every downstream front and recovery number.

## What this buys the Ekene story

Within this course the planted audit closes a loop that began three tiers ago. The Associate tier asserted the Ekene exponents; the Professional tier asserted a J-curve; this module has now demonstrated the tool that would catch either assertion being false against its own data. The teaching field is deliberately built so that every planted parameter is recoverable through the engines, which is not a luxury of synthetic data so much as a standard for real data: a curve set whose parameters CANNOT be recovered from its own table is a curve set you should not be using.

## The misconception to avoid

The misconception is deference: the header came from the lab, so the header wins. Headers are typed by people, copied between reports, and standardized by companies; tables come off instruments. When a machine-precision fit of the table contradicts the header, the probability mass sits overwhelmingly on a labelling error, and treating the header as authoritative propagates that error into every displacement calculation downstream. The reverse deference is just as wrong on a noisy table, where the header may encode calibration knowledge the five measured points cannot resolve; there the confidence interval, not the point estimate, is what you weigh the header against.
